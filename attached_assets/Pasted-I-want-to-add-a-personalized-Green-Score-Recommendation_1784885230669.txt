I want to add a personalized Green Score Recommendations section to the existing Green Scoring results page.

Please inspect the current frontend structure and reuse the existing Green Score API response, components, styling, authentication, and routing. Do not change the Green Scoring calculation logic.

Objective

After a user completes the Green Assessment and receives their score, show personalized recommendations based on:

Their business sector
Their energy score
Their water score
Their transportation score
Their certifications score
Their renewable energy share, when available

The recommendations must be sector-specific because different business sectors have different operational priorities.

Important Architecture Requirement

For this version, implement the recommendation engine in the frontend as a separate reusable utility file.

Create a file similar to:

src/utils/greenRecommendations.ts

or use the equivalent existing frontend folder structure.

Do not place all recommendation logic directly inside the results component.

The utility should expose a function similar to:

getGreenRecommendations({
  sector,
  categories,
  assessmentData
})

It should return an array of recommendation objects.

Each recommendation object should follow this structure:

{
  id: string;
  category: "energy" | "water" | "transportation" | "certifications";
  title: string;
  description: string;
  priority: "high" | "medium" | "low";
  impact: string;
  action: string;
}
Recommendation Priority Logic

Use the category score to determine priority:

Score below 40: high priority
Score from 40 to 69: medium priority
Score 70 or above: low priority

The weakest categories should appear first.

Show a maximum of 6 recommendations.

Do not display duplicate recommendations.

Your Green Improvement Plan

Add supporting text:

For every recommendation, display:

Category
Title
Short description
Priority badge
Expected impact
Clear action step

Use the existing application colors and card design.

Priority badges should be visually distinct:

High Priority
Medium Priority
Low Priority

Do not show technical IDs or algorithm information.

Do not show the simulation feature.

Display Rules

If there is no assessment result, do not display recommendations.

If the sector is missing:

Show a clear message asking the user to complete their business profile.
Do not silently use a random sector.
Do not break the page.

If one category is missing from the API response, continue generating recommendations from the categories that are available.

If the score is already high, recommendations should focus on maintaining performance and making gradual improvements instead of suggesting that the user is performing poorly.

Returning Users

When a returning user logs in and their previous Green Score is displayed, also display the recommendations associated with their latest score.

When they retake the assessment, regenerate the recommendations using the new category scores.

Optional Progress Feature

Add a simple checkbox or “Mark as planned” button to each recommendation.

For now, save this progress using local storage, namespaced by the user or business ID, so one user’s progress is not shown to another user.

Example storage key:

green-recommendation-progress-{businessId}

Do not mark recommendations as completed automatically.
