## Summary of implementation status

| Status | Count | Notes |
|---|---|---|
| ✅ Implemented | 33 | Logic works end-to-end within the frontend |
| ⚠️ Mocked / hardcoded | 17 | UI renders but data is static or simulated |
| 🔶 Partial | 5 | Feature exists but key component is missing or non-functional |
| ❌ Not implemented | 0 | All listed features have at least a UI representation |

**Key systemic risks across all features:**
1. **Dashboard and prescreening use hardcoded scores (credit 74, green 62) that are disconnected from the simulation engine.** The simulation engine computes scores correctly but those values never flow to Dashboard or LoanPrescreening.
2. **No data persistence.** All state lives in React context; a page refresh resets everything to defaults.
3. **All financial data (cash balance 18,500 JOD, existing loan 850 JOD, monthly revenue fallback 4,800 JOD, cash trend 14%) is hardcoded** in `mockBaseState()` and `buildAutoProfile()` — not sourced from any connected bank or tax system.
4. **Application submission has no backend.** The prescreening PDF is never sent anywhere. The reference number is random and not stored.
5. **All data source connections (CliQ, JoFotara, POS) are mocked.** Connecting them changes boolean flags and labels but retrieves no real data.
